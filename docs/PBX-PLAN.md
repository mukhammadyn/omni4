# PBX — план (2026-10-30)

Телефония CRM через onlinePBX: интеграция, запись, исходящие и входящие
звонки, всё, что есть в new-crm (`new-crm/professio_app_69f844`).
Бэкенд — общая функция `professional-crm-pbx-integration-call`
(`ucode/pbx-fn`).

## Что уже есть (PR #59)

- Карточка onlinePBX в «Интеграциях»: настройки, операторы, добавочные.
  Таблицы `pbx_settings`, `pbx_operators`, `pbx_calls`.
- Verto-транспорт `src/features/pbx/lib/verto` — умеет answer, hold,
  DTMF, transfer; в UI использован только mute.
- `CallButton` на карточках — сессия живёт внутри кнопки, входящий
  принять негде.
- `CallLog` и `useCallRecording` написаны, пункта меню журнала нет.
- Живьём ничего не проверено: нет аккаунта onlinePBX.

## Что умеет функция

| Методы | Для кого |
|---|---|
| `pbx_make_call`, `pbx_get_webrtc_credentials`, `pbx_log_call`, `pbx_get_recording`, `pbx_save_stereo_recording`, `pbx_save_transcript`, `pbx_list_untranscribed`, `pbx_debug` | любой проект |
| `crm_*` (история, пропущенные, передача сделки, сверка), поллер входящих (Redis, `pbx_sync_incoming`), входящий → сделка | только ARMADA: project-id зашиты в `business_invocation.go:40` |

### 10. Дашборд

- [ ] Аналитика звонков в CRM — собирается в «Дашбордах» руками
  (решено 2026-10-30), кода не нужно. Виджеты на `pbx_calls`:
  «Показатель» — всего звонков; «Показатель» с отбором
  `status = no_answer` — без ответа; столбцы по `status`; линия по
  `created_at` по дням с разбивкой по `direction`. По операторам —
  SQL-набор: `users_id` в журнале — guid строкой, имя только через join:

  ```sql
  SELECT u.full_name AS "Сотрудник", COUNT(*) AS "Звонков",
         ROUND(AVG(c.duration)) AS "Ср. длительность, с"
  FROM pbx_calls c LEFT JOIN core_users u ON u.guid::text = c.users_id
  GROUP BY u.full_name ORDER BY 2 DESC
  ```

## Права (2026-10-30)

- Включена ли телефония у человека, приложение узнаёт у функции
  (`pbx_get_webrtc_credentials`), а не чтением `pbx_settings`: там
  ключ API onlinePBX. Читает строку только экран настроек.
- [ ] Закрыть `pbx_settings` (и запись в `pbx_operators`) обычным
  сотрудникам. Отложено 2026-10-30: в omni4 и omni5 у сотрудников одна
  роль «Сотрудник», и у неё на `pbx_settings` все четыре права — ключ
  можно прочитать и поменять через API, а записью в `pbx_operators`
  назначить себя оператором. Закрыть — значит настраивать onlinePBX
  только входом ADMIN, либо сначала завести роль «Администратор»
  (отдельная задача про роли). Функции это не мешает: она читает
  таблицы своим ключом.
- Вкладка «Звонки» карточки видна по праву чтения `pbx_calls`.

## Порядок и блокеры

**1 → 2 → 4 (запись АТС) → 5 → 3 → 6** — «интеграция, запись,
делать и принимать звонки». 7–10 ждут воркер транскрипции, 11 — бэкенд.
