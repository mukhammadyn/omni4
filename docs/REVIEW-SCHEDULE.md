# Ревю «Графика работы» (2026-10-14)

Ревю коммитов `9756bc7..34c5170` (HRMS, «График работы»: модель,
календарь, окно смены, шаблоны, «Применить», вкладка сотрудника).
Находки собраны вручную и сверены независимым ревьюером. №1 проверен
прогоном модели во временном тесте. Ничего ещё не исправлено.

Строки — на коммит `34c5170`.

## Ждут решения

**Как вести себя с серией из шаблона** (№1, №5):

- **(а)** серию из шаблона правят только через «Применить»; окно смены
  правит один день;
- **(б)** окно правит и удаляет серию, но только у одного сотрудника.

**Прошлое** (№3): запрещать ли дату «с» в прошлом в «Применить»
и при создании новой серии.

## Можно чинить сразу

## Высокая серьёзность

### 1. Правка серии из шаблона ломает её рисунок

`model/schedule.ts:213-233` (`formOfSeries`), `ShiftDialog.tsx:120-125`.

`formOfSeries` сводит серию к одной форме. Время, тип, должность, филиал
и комментарий берутся из `rows[0]`, а порядок строк задаёт ответ API.
Дни недели — объединение дней всех дат, период — общий на всех
сотрудников. `save` пересобирает серию через `draftsOfForm`
и `rewriteSeries` при любой правке, даже если изменили только комментарий.

Что получалось в прогоне модели:

- цикл 2/2 на двоих со сдвигом: на каждого стало 31 смена вместо 16, то есть смена каждый день;
- недельный шаблон, где пятница 10–15: пятница стала 09–18;
- должность у всех — из первой строки.

Ещё:

- перерыв шаблона заменяется на `DEFAULT_BREAK` (`model/schedule.ts:175`);
- цикл начинает пропускать праздники, хотя по шаблону работает и в них;
- дни, снятые кнопкой «Только <день>», возвращаются.

Решение — см. «Ждут решения».

### 5. «Удалить» снимает серию у всех её сотрудников

`ShiftDialog.tsx:132`, `api/schedule.ts:182`.

`removeSeries` удаляет `rewriteSeries(rows, [], today).remove`, а `rows` —
вся серия по всем сотрудникам (`useSeries`). Шаблон применён
к 50 людям — щелчок по смене одного и «Удалить» снимают будущие смены
всем пятидесяти. При этом «Только <день>» удаляет строку одного
сотрудника — кнопки ведут себя непоследовательно.

### Н1. «Удалить» без подтверждения

`ShiftDialog.tsx:266`. Вместе с №5 это одно нажатие, которое необратимо
удаляет будущие смены у всех сотрудников серии. Нужен `ConfirmDialog`
с числом затронутых людей и смен.

## Средняя серьёзность

### 2. «Новая смена» на вкладке сотрудника — без сотрудника

`ShiftDialog.tsx:50-52`, `:73-78`; `api/schedule.ts:146`, `:157`.

`ShiftForm` берёт сотрудника в инициализаторе `useState`, один раз,
из общего списка `useScheduleEmployees()`. У новой смены форма
рисуется сразу, без проверки загрузки. Вкладка (`EmployeeSchedule`)
грузит сотрудников с отбором по guid — это другой ключ кэша, поэтому
общий список при первом открытии пуст. Итог: поле сотрудников пустое,
должность и филиал тоже; сохранение откажет «выберите сотрудника».
Данные не портятся. В календаре графика не проявляется — там список
в кэше.

Та же гонка — `ApplyTemplateDialog.tsx:42-48`: шаблон и филиал
по первому сотруднику.

Исправление: не рисовать форму, пока `useScheduleEmployees().loading`.

### 3. Прошлое переписывается (частично)

- **«Применить шаблон»** (`ApplyTemplateDialog.tsx:127`): у даты «с» нет
  нижней границы. С «Заменить существующие» `shiftIdsOf(from, to)`
  (`api/schedule.ts:197`, `:252`) удалит прошлые смены, а новые запишутся
  задним числом. Подтверждено.
- **Окно смены**: новая смена на один прошлый день допустима — по решению
  «смена из одного дня правится целиком». Дыра — новая *серия* с прошлым
  «с»: `draftsOfForm` прошлое не режет, а `rewriteSeries` вызывается
  только при правке (`ShiftDialog.tsx:125`).

Решение — см. «Ждут решения».

### 4. Запись не атомарна, порядок опасный

`api/schedule.ts:214-217` (`writeShifts`), `:296-308` (`useSaveTemplate`).

`writeShifts` сначала удаляет, потом пишет; порции по 1000 идут подряд,
атомарна только одна порция upsert-many. Сбой посередине на правке
серии или «Применить с заменой» — смены пропали. `useSaveTemplate`
удаляет старые дни до записи новых — шаблон может остаться без дней.

Исправление: сначала записать, потом удалить старые guid. У новых строк
guid свои, а `shiftIdsOf` считается до записи, поэтому новые строки
в удаление не попадут. Худший исход при сбое — дубли, а не потеря.

### 6. Окно смены грузит всю серию

`api/timesheet.ts:42-48` (`useAll`), `ShiftDialog.tsx:52`,
`model/schedule.ts:240-246`.

Чтобы открыть окно, `useSeries` дочитывает все страницы серии: шаблон
на год × 50 человек — 13+ запросов. Пока они идут, окно возвращает
`null` — щелчок по смене выглядит как «ничего не произошло». Сохранение
удаляет и переписывает все будущие строки серии. Снимается вместе
с решением по №1.

### Н2. «Только <день>» удаляет и прошлые дни

`ShiftDialog.tsx:134-135`. `skipDay` удаляет строку любой даты. Для серии
из нескольких дней это нарушает правило «прошлое — норма табеля».
Исправление: кнопка только для `open.date >= today`.

### Н3. Групповая смена на один прошлый день не правится

`model/schedule.ts:241`. `rewriteSeries` проверяет `rows.length === 1`,
а не «одна дата». Смена на один день, созданная сразу на нескольких
сотрудников, в прошлом не правится: изменение пустое, а тост пишет
«Смена сохранена». Расходится с решением «смена из одного дня правится
целиком». Исправление: `new Set(rows.map((r) => r.date)).size === 1`.

## Низкая серьёзность

### 7. Гонки загрузки (частично)

- Праздники (`api/schedule.ts:128-133`) грузятся без признака загрузки;
  `save` и `submit` его не ждут. Если сохранить раньше, смены лягут на праздники. Окно короткое,
  касается только серий и недельного шаблона. Вдобавок
  `placeholderData: previous` (`features/item/api/items.ts:63`): после
  смены периода до загрузки видны праздники прошлого.
- `WorkSchedules.tsx:64-65`: при `future[index] === undefined` удаление
  шаблона разрешено — и пока запрос идёт, и при его ошибке.

### 8. Пустая клетка по оси «Должность» подставляет сотрудника

`ScheduleCalendar.tsx:285`: `employeeId: row.employees[0]!.id` и на строке
должности. В окно подставляется случайный человек должности.
Исправление: на строке должности `employeeId` не передавать.

### 9. Мелочи

- **а.** `useDeleteTemplate` (`api/schedule.ts:321-327`) не очищает
  `employees.hr_work_schedules_id`; проверка удаления смотрит только
  смены впереди. В интерфейсе — «без шаблона» по мёртвой ссылке.
- **б.** Пустое изменение показывает тост успеха: правка серии целиком
  в прошлом — «Смена сохранена», «Удалить» — «Смена удалена».
- **в.** Экраны графика не проверяют права на запись; образец —
  `CandidatePage.tsx:148` (`can.update`). Бэкенд проверяет сам, так что
  это только интерфейс.

## Снято

## Исправлено (2026-10-14)

Решения по №1/№5 и №3 взяты из HRMS (`hrms/docs/adr/0004`): правка
и удаление серии — по двум осям «какие дни × кому», строки
обновляются на месте только тронутыми полями, дыры не заполняются,
удаление по умолчанию — одна строка. Серию (окно смены и «Применить»)
нельзя начать в прошлом; один прошлый день — можно.

- №1, №5, Н1 — `editSeries`/`scopedRows` (`model/schedule.ts`), шаг подтверждения в `ShiftDialog` с числом смен.
- №2, №6 — окно ждёт список сотрудников и серию, показывает «Загрузка…».
- №3 — `apply.pastFrom`, `shift.pastFrom`.
- №4 — `writeShifts` и `useSaveTemplate`: сначала запись, потом удаление.
- №7 — `useHolidays` отдаёт `loading`, сохранение ждёт; удаление шаблона ждёт счёт смен.
- №8 — на строке должности сотрудник не подставляется.
- №9а — удаление шаблона снимает его из карточек; 9б — пустое изменение — «Менять нечего»; 9в — кнопки окна смены по правам `hr_shifts`.
- Н2 — «Только <день>» только с сегодня; Н3 — «одна дата», а не «одна строка».

## Второй круг (2026-10-14)

Ревю исправлений выше. Решения — по HRMS (`hrms/docs/adr/0004`,
`udevs_hrms_admin/src/modules/Shifts/plan.ts`, `ShiftModal.tsx`).

- Растянутая смена из одного дня сохранялась одним днём молча.
  Теперь дни формы без строки у участника — пропуски: показываются на
  шаге подтверждения, заполняются только галочкой. У серии из шаблона
  пропусков нет — выходные цикла не дыры, продлевают её «Применить».
- Занятые дни: новая строка на день, где у человека уже стоит смена,
  — «оставить как есть» или «перезаписать» (строка переходит в серию).
  Перенос смены на занятый день — ошибка. «Применить шаблон» этой
  проверки нет — в HRMS такой функции нет, решение не принято.
- Новые строки: должность — из карточки каждого, филиал — из формы,
  иначе из карточки (`plan.ts`, fieldsFor).
- Перерыв пересчитывается, только если тронули время.
- «Удалить» на прошлом дне серии — по умолчанию «с этого дня».
- Отказ проверки «есть ли дни раньше» — причина в окне, а не вечная загрузка.
- Поиск календаря — только на сервере; убран проп `PeriodBar.right`.

Не правилось: удаление считается по изменённой форме (как в HRMS);
итоги календаря на границе последней порции; право на изменение
чужих смен при перезаписи проверяет бэкенд.
