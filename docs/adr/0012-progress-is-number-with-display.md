# 12. Индикатор — число с пометкой вида, а не свой тип бэкенда

Дата: 2026-10-01
Статус: принято

## Контекст

В прототипе есть тип поля `progress` — «Маржа» в `products.html`:
число 0–100, нарисованное полоской с процентом. Синяя полоса, при 100
и больше — зелёная, ниже 50 — оранжевая.

У бэкенда такого типа нет. Незнакомый тип он не отклоняет, а молча
заводит строкой: `helper.GetDataType` (`pkg/helper/convert.go:137`)
возвращает `VARCHAR`. Сортировка пошла бы по буквам («9» > «50»),
а фильтры «больше / меньше» не работали бы вовсе — бэкенд сравнивает
числами только `NUMERIC_TYPES` (NUMBER, FLOAT). Править бэкенд
из этого репозитория нельзя.

## Решение

**В базе индикатор — обычный NUMBER (колонка FLOAT), а вид — ключ
`number_display: "progress"` в `attributes` поля.** Бэкенд хранит
`attributes` как свободный JSONB и отдаёт обратно как есть; так же
у нас живут `validation` и `defaultValue`.

Внутри фронта это свой тип `PROGRESS` (`features/table/model/types.ts`):
в списке типов, в иконке, в ячейке. Перевод — в двух местах и только
там: `api/normalize` читает NUMBER с пометкой как PROGRESS,
`api/fields` (`storedType`) отправляет PROGRESS как NUMBER с пометкой.

Для ячейки индикатор — вид `number`: правка, приведение значения,
фильтр и сортировка у него числовые без единой новой ветки. Свой у него
только рисунок (`ProgressCell`).

Смена «число ↔ индикатор» колонку не трогает: для бэкенда тип не
меняется, поэтому редактор поля не предупреждает о потере данных,
и переименование не делится на два запроса.

## Цена

- **Старая админка, мобильные клиенты и экспорт видят обычное число.**
  Значение то же, рисунка нет.
- **Пометка висит и у бывшего индикатора**, если ему сменили тип
  не на NUMBER: читается она только у NUMBER, так что вреда нет, но
  ключ в `attributes` остаётся.
- **Список числовых типов в двух местах знает PROGRESS отдельно:**
  `item/model/pivot.ts` (по чему складывать) и `shared/lib/relation-label.ts`
  (разряды в подписи связи). Новый числовой «вид» придётся дописывать
  туда же.

Если бэкенд заведёт свой тип индикатора, перевод убирается из
`normalize` и `fields`, а всё остальное остаётся как есть.
