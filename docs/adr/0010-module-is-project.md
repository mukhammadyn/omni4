# 10. Module — отдельный Project

Дата: 2026-09-30
Статус: принято

## Контекст

omni4 делится на модули: CRM, HRMS, Склад, Финансы, Проекты
(см. [[Module]] в CONTEXT). У каждого своё меню, и активен ровно один.
Ложиться на платформу модуль мог двумя способами: папкой меню внутри
одного [[Project]] или отдельным Project.

## Решение

**Каждый модуль — отдельный Project ucode.** Переключатель модулей
в сайдбаре — это переключение проекта.

Сами проекты в ucode пока не заводятся: сначала экраны, потом данные.

## Цена

- **Переключение модуля — переход, а не вкладка.** [[Session]]
  связывает пользователя ровно с одним Project, поэтому смена модуля
  выпускает новую пару токенов, как и смена [[Environment]]. Держать
  два модуля открытыми в двух вкладках браузера нельзя — сессия одна.
- **Связи между модулями не делаются [[Relation]].** Relation живёт
  внутри одного Project: сделка CRM не может сослаться на сотрудника
  HRMS обычным полем-связью. Как модули видят данные друг друга —
  отдельное решение, когда понадобится первый такой случай.
- **Права и роли — по модулю.** [[Client Type]] и роли принадлежат
  проекту, человек заводится в каждом модуле, куда у него есть доступ.

## Почему всё-таки так

Модули независимы по данным, правам и жизненному циклу: HRMS без
CRM — нормальная поставка. Отдельный Project даёт это даром, а папки
в одном проекте потребовали бы разделять права и таблицы вручную.
